# okf-parser 0.25.0

- `okf-parser-duckdb` now derives optional `.schema.sql` paths from the explicit type-spec template, executes each trusted script whole on a fresh in-memory DuckDB connection, and validates the RFC 0006 catalog post-condition.
- DuckDB remains the SQL parser, binder, planner, and type normalizer; the TypeScript implementation introduces no DDL grammar.
- Catalog types are projected losslessly into the public TypeContract, including Decimal precision/scale, safe versus unsafe integers, UUID, temporal types, lists, and unsupported identities.
- `compileDeclaredTypeContracts` and `exportDeclaredJsonSchema` provide the complete Node application surface without Python or a loopback transport.
- Missing declarations remain ordinary opt-out; ambiguous paths, SQL failures, and missing/multiple post-condition tables fail explicitly.
- Closes the read-only TypeContract/declaration portion of #69; typed materialization remains in #70.
