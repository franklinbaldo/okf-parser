# okf-parser 0.3.0

- Number ordered lists consecutively, so `1. 2. 3.` is canonical form instead of
  collapsing every marker to `1.`, keeping the source of a numbered plan
  readable in a diff.
- Decide the marker while rendering, from the list node itself, so a list is
  never zero-padded to an even width. Appending a tenth item no longer rewrites
  the nine lines above it as `01.` to `09.`, and a list starting at `101` is
  written `101. 102. 103.` rather than renumbered.
- Keep plain numbering for a list that would exceed CommonMark's nine-digit
  marker limit, which would otherwise turn a list starting at `999999999` into
  an ordinary paragraph.
- Format and inspect Markdown through one shared dialect, so frontmatter and GFM
  tables are seen the same way on both sides.
- Refuse to write a file whose protected block structure the rewrite would
  change, reporting it in `skipped_paths` instead. Protected means the sequence,
  nesting and tag of every block, block attributes such as an ordered list's
  `start`, and the content of code blocks, raw HTML and frontmatter. Inline
  content is outside this guarantee.
- Confine every dependency on mdformat internals to `okf_parser.markdown_style`,
  which fails fast with a named symbol if an unsupported mdformat is installed,
  and narrow the supported range to `>=1,<1.1`.
