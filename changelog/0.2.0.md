# okf-parser 0.2.0

- Validate YAML frontmatter strictly with Pydantic at the point it enters the
  program, so an unsupported value such as `!!binary` or `!!set` is reported
  rather than silently coerced into a `str` or an unordered list.
- Report non-string frontmatter keys as `OKF001` instead of crashing the run.
- Report cyclic YAML anchors as `OKF001` instead of raising `RecursionError`.
- Treat unparseable link targets as non-links instead of raising `ValueError`.
- Accept an empty `---`/`---` frontmatter block as valid frontmatter.
- Infer frontmatter links only from whitespace-free targets, so prose ending in
  `.md` no longer produces a spurious `OKF101` and a junk link row.
- Detect headings with CommonMark tokens, so `#` inside a fenced code block no
  longer satisfies `OKF005` or triggers a false `OKF008`.
- Require a level-one heading to carry text, so a bare `#` satisfies neither
  `OKF005` nor `OKF007`.
- Discover Markdown files case-insensitively, matching link classification.
- Keep unresolved link targets out of the NetworkX projection instead of adding
  attribute-less phantom nodes.
- Report an absent concept title as `None` rather than `nan` in graph nodes.
- Skip unreadable files during formatting and list them as `skipped_paths`.
- Write formatted Markdown only after every file has been formatted.
- Report a new `succeeded` field, and exit non-zero, when `format --write`
  leaves any file unread.
- Raise `BundleExportError` and accept `--overwrite` when materializing a bundle
  into a DuckDB schema that already holds tables.
- Express every domain record as a frozen Pydantic model.
