# okf-parser 0.5.0

Frontmatter scalars are now preserved as authored text. YAML still provides the
mapping and list structure, and explicit `null` remains null, but values such as
`0012`, `false`, `42` and `2026-01-01` no longer acquire a type merely because a
YAML loader recognizes their spelling.

Schema export follows the same rule: scalar fields are strings by default.
`schema --infer-types` opts into best-effort inference across every observed
value of a field, using pandas conversions for numeric and temporal values and a
conservative boolean recognizer. A single incompatible observation falls the
field back to string rather than producing a partial union.

Repeatable `--cast FIELD=TYPE` options declare strict overrides. Supported types
are `string`, `boolean`, `integer`, `number`, `date` and `datetime`; invalid,
incompatible or unused casts are reported instead of silently ignored. Dotted
paths address nested fields, and casts apply to scalar list items at that path.

The JSON Schema and Zod exporters now derive requiredness from all documents of
a concept type, merge list and nested-object observations, and expose the same
options through the Python service, CLI and MCP tool.
