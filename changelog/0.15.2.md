# okf-parser 0.15.2

## Declared schema correctness

Follow-up fixes after RFC 0006's initial schema-export implementation:

- bind a declaration to the exact non-temporary DuckDB catalog table before
  reading its columns, so a temporary homonym cannot leak into the schema;
- resolve table identity with DuckDB's ASCII case-insensitive identifier
  semantics while preserving the catalog spelling;
- export supported columns that are declared but not yet observed as optional
  properties;
- keep scalar declarations from accidentally typing observed list items;
- fail explicitly on an existing derived-path collision or malformed
  `.schema.sql` instead of silently treating the declaration as absent until
  RFC 0006's advisory diagnostics channel is implemented;
- reserve the source `type` column during `import`, so input data cannot
  override the command's canonical `--type` identity.

The larger RFC 0006 decisions around physical-type preservation,
declared/effective/observed schema modes, and `apply`/`duckdb` materialization
remain intentionally unchanged.
