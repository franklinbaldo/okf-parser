# okf-parser 0.20.1

- Core link relations now come only from authored Markdown links; arbitrary frontmatter strings ending in `.md` remain metadata instead of creating graph edges or `OKF101` warnings (#44).
- The Python and TypeScript implementations share that relation boundary; the existing frontmatter-link classifier remains available for compatibility but is no longer authoritative bundle semantics.
- Python and TypeScript DuckDB integration tests pin the same body-link count, so materialized `links` tables cannot silently reintroduce frontmatter-derived edges.
- `docs/architecture.md` distinguishes strict authored OKF conformance from explicit source-adapter/projection policy (#58).
- The README GitHub Action example is pinned to the current release, and source-release verification fails when that documented ref drifts from the package version (#39).
