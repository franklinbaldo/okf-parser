# okf-parser 0.42.3

- renames `.github/workflows/release.yml` to `publish.yml`: the PyPI
  Trusted Publisher for `okf-parser` was registered against the workflow
  filename `publish.yml` (proven by the one PyPI upload that ever
  succeeded, the temporary `v0.41.3` shim), not `release.yml`. Every
  attempt to publish under the newer filename failed OIDC token exchange
  with `invalid-publisher: valid token, but no corresponding publisher`
  — a filename mismatch, not a credentials or permissions problem.
  `docs/releasing.md` is corrected to match;
- fixes the bundled-script verification check to accept
  `.data/scripts/okf-parser.exe` on Windows wheels, not just the
  extension-less Linux/macOS name (the Windows wheel itself was always
  fine; only this check's exact-name comparison rejected it).
