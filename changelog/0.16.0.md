# okf-parser 0.16.0

## Lossless declared-type IR

`.schema.sql` declarations no longer collapse immediately into the six-value
`CastKind` vocabulary. The catalog-normalized DuckDB logical type now survives
through the shared schema contract, including DECIMAL precision/scale, UUID,
naive versus timezone-aware timestamps, integer widths, and list element types.
List declarations retain both the full container identity (for example
`BIGINT[]`) and the recursively typed element contract.

`schema --spec-template` now exports declared intent even when current data
diverges; one malformed observation no longer widens a declared column to string.
JSON Schema and Zod map the physical type independently, with
`x-okf-duckdb-type` retaining the exact DuckDB identity in JSON output.

RFC 0006 decisions 5, 5a, 9 and 10 are closed around a simpler rule for future
relational materialization: lossless raw value plus per-value DuckDB `TRY_CAST`,
without a whole-column fallback or an OKF-specific lexical exactness grammar.
`apply`/persistent `duckdb` wiring remains for follow-up releases.
