# okf-parser 0.20.0

## Pydantic schema target

`okf-parser schema . --format pydantic` prints one deterministic importable Pydantic v2 module using the same `TypeContract` consumed by JSON Schema, Zod, and runtime Pydantic models.

- no new command hierarchy or required configuration;
- aliases are automatic for Python keywords, invalid identifiers, leading-underscore keys and protected `model_*` names;
- dynamic and source-generated models share the same Pydantic projection policy;
- optional non-nullable fields preserve omission versus explicit `null`;
- nested generated model names are registered compilation-wide and collisions report both structural paths;
- generated source uses children-first class emission and immediately evaluated annotations, so callers do not need a generator-specific `model_rebuild()` step;
- declared `TIMESTAMP`, `TIMESTAMPTZ` and list types are covered directly by source-generation regressions;
- generated Pydantic identifiers are deterministically bounded with stable SHA-256-derived suffixes; long class names retain CapWords spelling, while long aliases, literals and annotations use canonical multiline source so valid long OKF names remain inside the repository Ruff contract;
- checked-in short and adversarial generated-module snapshots are byte-for-byte pinned and pass the repository Ruff format/lint gates;
- textual CLI schema output is byte-identical to the renderer payload when it already has a trailing newline, so redirecting Pydantic or Zod stdout adds neither a missing newline nor an extra blank line;
- CLI regressions exercise both `--format pydantic` and `--format zod` through the public command surface and compare captured stdout byte-for-byte with the service payload;
- RFC 0001 is accepted with the implementation in place.
