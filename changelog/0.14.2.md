# okf-parser 0.14.2

## RFC 0005: relational writes to frontmatter fields

Proposes `okf-parser apply PATH --sql "UPDATE concepts SET ... WHERE ..."`,
closing the direction `duckdb` and `schema` never opened: mutating frontmatter
in bulk instead of only reading it.

- runs the caller's SQL against a flattened, ephemeral view of the concept
  relation, so plain `SET field = value` works without JSON-path expressions
  against `frontmatter_json`;
- dry-run by default, matching `format`;
- writes back through a round-trip-preserving YAML loader instead of
  reserializing frontmatter wholesale, so an untouched key, comment or blank
  line survives;
- refuses to target filesystem-derived columns (`concept_id`, `logical_key`,
  `path`);
- validates every touched document with `check` after writing and surfaces
  new nonconformance instead of silently accepting it;
- requires idempotency: running the same invocation twice produces no second
  diff.

Closes #26 as an accepted design; implementation follows in a later release.
