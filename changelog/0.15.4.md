# okf-parser 0.15.4

## RFC 0008: effect-aware MCP mutation tools

Proposes replacing the server-wide read-only MCP assumption with per-tool
effect semantics:

- keep the default MCP profile read-only for compatibility;
- add an explicit `serve --allow-write` profile for commit-capable tools;
- expose separate preview and write MCP tools where one service already has a
  dry-run/write split;
- declare standard MCP `readOnlyHint`, `destructiveHint`, `idempotentHint` and
  `openWorldHint` annotations conservatively from each tool's maximum effect;
- keep annotations descriptive only — service-layer validation and the
  write-enabled server profile remain the enforcement boundaries;
- reuse the existing service functions instead of introducing MCP-specific
  mutation logic;
- allow the Python MCP surface to land without blocking on TypeScript write
  parity.

No MCP write behavior is implemented in this release; RFC 0008 remains
`proposed`.
