# okf-parser 0.15.4

## RFC 0008: effect-aware MCP mutation tools

Proposes replacing the server-wide read-only MCP assumption with per-tool
effect semantics:

- keep the default MCP profile **commit-disabled** for compatibility rather
  than claiming the whole server is side-effect-free;
- add an explicit `serve --allow-write` profile for first-class commit tools;
- expose separate preview and write MCP tools where one service already has a
  dry-run/write split;
- declare standard MCP `readOnlyHint`, `destructiveHint`, `idempotentHint` and
  `openWorldHint` annotations conservatively from each tool's maximum effect;
- annotate the existing `schema` tool conservatively because RFC 0006 may
  execute trusted `.schema.sql` DuckDB SQL when `spec_template` is used;
- keep annotations descriptive only — server capability, host authorization
  and service-layer invariants remain the enforcement boundaries;
- reuse the existing service functions instead of introducing MCP-specific
  mutation logic;
- allow the Python MCP surface to land without blocking on TypeScript write
  parity.

No MCP commit tools are implemented in this release; RFC 0008 remains
`proposed`.
