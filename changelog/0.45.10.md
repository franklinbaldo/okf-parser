# 0.45.10

- Route DuckDB materialization and application services through the same automatic engine resolution used by the public `load_bundle` API. When the compatible Rust core is installed, `attach_okf`, `export_duckdb`, `check`, `inventory`, `graph`, and `init` now use it instead of silently falling back to the Python-only loader.
- Route the public `validate_path` API through that same engine selection while preserving relational-schema and type-spec validation semantics.

Fixes #261.
