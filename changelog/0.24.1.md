# okf-parser 0.24.1

- successful RFC 0005 `apply` previews now return an opaque versioned `preview_token` that commits to the invocation snapshot, exact SQL and exact candidate document state;
- `apply_bundle(..., write=True, expected_preview_token=...)` fails closed when the recomputed candidate differs from the reviewed preview;
- token mismatch is conflict-shaped and leaves the live bundle unchanged, including when an intervening edit makes the operation a no-op;
- nondeterministic DuckDB expressions cannot silently commit a candidate different from the one reviewed;
- one-shot writes that omit `expected_preview_token` retain the existing behavior and still perform the final whole-bundle freshness check.
