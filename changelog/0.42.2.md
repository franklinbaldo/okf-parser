# okf-parser 0.42.2

- builds real per-platform wheels for `okf-parser` — manylinux_2_28
  (x86_64, aarch64), Windows x64, macOS (x86_64, arm64) — via
  `PyO3/maturin-action`, replacing the bare `ubuntu-latest` build that
  produced an unqualified `linux_x86_64` wheel tag PyPI rejects on upload;
  this was the direct cause of v0.41.3 publishing only its sdist and
  leaving the release permanently half-published (okf-parser#147);
- switches the manylinux base image from the default (`auto`) to `2_28`:
  the bundled `libduckdb-sys` build refuses the older container's legacy
  C++ ABI outright (`DuckDB does not provide extensions for this (legacy)
  CXX ABI`);
- generalizes `scripts/release_contract.py` and `scripts/registry_state.py`
  from one hardcoded `python-wheel` artifact kind to one kind per target
  platform, so the release manifest and the resumable-publish registry
  gate correctly track and verify all five wheels instead of only one;
- adds a same-job smoke test that installs each Linux wheel with the Rust
  toolchain removed first, and a post-publish job that installs
  `okf-parser` from the real public PyPI index on Linux, Windows and
  macOS — both fail loudly instead of silently falling back to a slow
  from-source Rust build if a wheel ever goes missing for a supported
  platform again;
- extends `release-dry-run.yml` with the same wheel matrix so a PR
  touching release configuration exercises the full build once more,
  before any tag is pushed.
