# okf-parser 0.37.0

- successful RFC 0005 `apply` previews now return an opaque deterministic `preview_token`;
- the token commits to the coherent baseline snapshot, exact SQL/options and exact physical candidate bytes produced by the shared writer;
- `apply_bundle(..., write=True, expected_preview_token=...)` fails closed when recomputation differs, including nondeterministic DuckDB SQL and reviewed no-ops whose source changed;
- one-shot writes may omit the token and retain existing behavior;
- final whole-bundle freshness/staging validation remains mandatory after token verification, so the token does not replace optimistic conflict detection;
- the transport-neutral service forwards `expected_preview_token` while existing CLI/MCP one-shot contracts remain unchanged in this slice.
