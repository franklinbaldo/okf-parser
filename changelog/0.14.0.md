# okf-parser 0.14.0

Prunes `.okf/` during discovery, so the directory the format reserves to
describe a bundle stops being counted as content of it.

- adds `.okf` to the pruned directories, beside `.git`, the caches and `.venv`;
- keeps `.okfignore` for what it is — a choice made by whoever maintains a
  mixed repository — while this list stays what is never content in any
  bundle.

The layout proposed in #25 keeps a type specification at
`.okf/specs/<type>.md` inside the bundle. Because discovery descended there,
that specification became a concept of the very bundle it describes, so it
required a `type` of its own — and that type would then require its own
specification inside every bundle that had one. A rule meant to eliminate
undocumented types would have mandated duplicating the same document across
bundles.

Measured on a repository that adopted the rule with eleven types across six
bundles: `check` either reported six bundles failing for a specification
without `type`, or required six copies of the same document.
