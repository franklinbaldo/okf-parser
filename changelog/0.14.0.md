# okf-parser 0.14.0

## `.okfignore` follows `.gitignore` semantics

**Breaking for existing `.okfignore` files and `--exclude` patterns.** RFC 0004.

- a pattern without a separator now matches its name at any depth; a separator
  anchors it at the bundle root;
- a trailing `/` matches directories only;
- `!` re-includes, and the last pattern that matches a path decides its fate;
- `[abc]` and `[!abc]` character classes are supported;
- `#` comments, blank lines, unescaped trailing spaces and `\#` / `\!` escapes
  follow `.gitignore`;
- one documented deviation: a negation works even when a parent directory is
  excluded, which `.gitignore` cannot express, because a negation that silently
  does nothing is the surprise this feature exists to prevent;
- discovery still prunes an excluded directory whenever no negation is present,
  so the large vendored tree that motivated pruning is unaffected;
- both runtimes are driven by `conformance/exclusion.json`.

Migration: `*.md` becomes `/*.md` to stay root-level, `vendor` becomes
`/vendor` to stay root-only, and a literal leading `!` needs `\!`.

## Optional type-specification rule

Adds `check --require-spec TEMPLATE`, which requires every producer-defined type
in use to have a specification document at the path its template derives.

- derives the document path from the type name, so `type` stays a stable
  identity and no second field can disagree with it;
- shares one slug derivation between the Python and TypeScript runtimes through
  `conformance/type-spec-slugs.json`: lowercase, accents and cedillas removed,
  whitespace and `/` turned into hyphens, remaining non-alphanumerics dropped;
- reports `OKF010` as a warning by default, because a bundle mid-adoption
  legitimately has legacy types without a document;
- promotes `OKF010` to a normative error under `--normative-spec`;
- reports a type whose name yields no slug against the template itself instead
  of failing the run;
- exposes the same rule through the Python and TypeScript CLIs, the MCP `check`
  tool, `validate_path` and `checkBundle`;
- leaves `check` byte-identical when the rule is not requested.

Closes #25.

## Release package-content contract

Adds the package-content phase of RFC 0003 without enabling publication.

- inspects the member list of the wheel, source distribution and both npm
  tarballs recorded in the immutable release manifest;
- requires each distribution to ship its importable modules, executables, type
  declarations, README and licence rather than metadata alone;
- rejects caches, virtual environments, editor state, credential files, private
  keys, compiled bytecode and local databases in any distribution;
- rejects source-only and development paths that belong to the repository
  instead of an installed consumer, such as TypeScript sources, test suites and
  compiler configuration inside npm tarballs;
- rejects archive members outside the expected package root, non-regular
  archive members and unsafe or traversing member names;
- excludes repository workflow automation and `.gitignore` from the Python
  source distribution;
- covers complete, incomplete, polluted and escaping archives with fixtures;
- runs `verify-contents` in the release dry run before registry preflight.

This version still has no registry write permission, OIDC publication job,
protected release environment, tag trigger or GitHub Release finalizer.
