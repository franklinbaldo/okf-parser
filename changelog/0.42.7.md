# okf-parser 0.42.7

- removes DuckDB from the packaged Rust executable, and with it the macOS
  and Windows wheels 0.42.6 published broken. Those wheels linked a
  `libduckdb` they did not ship, so the command failed at startup with a
  loader error. Only Linux worked, because `auditwheel` runs inside the
  manylinux container and vendored the library there; nothing equivalent
  runs for macOS or Windows, and Linux passing was never evidence that they
  would;
- the executable never needed that DuckDB. The Python distribution already
  depends on `duckdb`, and `okf-parser duckdb` exports through it via Ibis
  — an implementation that also materializes typed tables, which the Rust
  writer did not. The Rust copy served only the private `__engine-duckdb`
  subcommand, and nothing calls it: the Python and TypeScript bridges both
  drive `__engine-load` and `__engine-facts`, and no other caller exists.
  `duckdb`, `rust-core/src/database.rs` and `__engine-duckdb` are gone;
- this drops 111 crates from the lockfile, the whole Arrow and DuckDB C++
  tree. Wheel jobs no longer compile an amalgamation, and neither does the
  collect job's separate build of the npm native binary, which still paid
  that cost even after the wheels stopped;
- `scripts/check_no_duckdb_link.py` runs in every wheel job and fails the
  build if the executable names a DuckDB library or a wheel ships one. It
  reads the binary's own import names, so it also covers the cross-built
  wheel no runner can execute. Verified against the broken 0.42.6
  artifacts: it rejects all three failure shapes;
- each wheel is now installed and exercised on a runner of its own
  architecture before publication — `--version`, `check`, and the public
  `duckdb` command against a real database. Previously only the manylinux
  x86_64 wheel ran before publishing and the others were installed solely
  against the public index afterwards, so CI could prove a release broken
  only after making it public. macOS wheels build on `macos-15` and
  `macos-15-intel` rather than building both on an arm64 `macos-14`.
