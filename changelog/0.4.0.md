# okf-parser 0.4.0

- Exclude subpaths from a bundle with an `.okfignore` beside the content, or
  with a repeatable `--exclude` for a single run. A repository that keeps OKF
  knowledge next to code and vendored dependencies previously had no root that
  validated cleanly, which forced it to check each bundle separately and left
  every link between bundles permanently unresolvable.
- Accept `--exclude` on `check`, `inventory`, `graph`, `format` and `duckdb`,
  and on the matching MCP tools. `load_bundle`, `validate_path` and
  `format_path` read `.okfignore` themselves and take an `exclude` sequence.
- Never read or write an excluded file, so `format --write` on a repository
  root leaves vendored documents untouched.
- Prune an excluded directory during the walk rather than filtering afterwards,
  so a vendored dependency of several hundred documents is not traversed.
- Match patterns as anchored globs relative to the bundle root, where `*` and
  `?` stay inside one path segment and `**` spans segments. This is narrower
  than `.gitignore` on purpose: without anchoring, a pattern would widen its own
  scope and silently drop documents the author meant to validate.
- Report an exclusion file that exists but cannot be decoded, naming the path,
  instead of validating a tree the author believed was filtered.
- Pin the GitHub Action example in the README to an exact version. The `@v1` it
  advertised has never existed, so following the Quick start broke a new
  consumer's CI.
