# okf-parser 0.15.0

## `apply`: relational writes to frontmatter fields

Implements RFC 0005 (#26): `okf-parser apply PATH --sql 'UPDATE "Rotina" SET ... WHERE ...'` mutates frontmatter fields in bulk through DuckDB SQL,
closing the direction `duckdb`/`schema` never opened — reading the bundle as
relations without ever writing back.

- materializes every concept type as its own table, named for the exact
  authored `type` value, inside one in-memory DuckDB database; `--sql` is
  handed to DuckDB mostly as-is, so its own parser/binder resolve
  identifiers and a type-name collision surfaces as DuckDB's own "table
  already exists" error;
- `--sql` accepts a bounded script: zero or more leading
  `ALTER TABLE ADD/DROP/RENAME COLUMN` statements followed by exactly one
  trailing `UPDATE`, run as a single DuckDB transaction that rolls back
  whole on any failure;
- `ADD COLUMN` backfills a field bundle-wide, `DROP COLUMN` removes it,
  `RENAME COLUMN` renames it and carries the value across — each
  statement's effect is read from DuckDB's own catalog before/after that
  statement, never from parsing the SQL. Frontmatter is compiled directly
  from the final relational state against the original document, so a
  chain of renames, a drop-then-recreate, or an `UPDATE` that happens to
  produce the same result all compile to the same diff;
- `type` is an ordinary writable column: `SET type = ...` migrates a
  document to a new type, detected the same way as any other field change
  via the row's `__okf_concept_id`;
- reserved `__okf_path`/`__okf_concept_id`/`__okf_logical_key` columns and
  the read-only `__okf_body`/`__okf_body_lines`/`__okf_frontmatter` columns
  (Markdown body, its line-split projection, and the exact raw YAML
  frontmatter block) are protected; a script that touches them, adds a
  non-`VARCHAR` column, or changes row cardinality is rejected after
  execution, by inspecting the result;
- writes go through a round-trip YAML loader that preserves comments, key
  order, BOM, and CRLF; a document that can't round-trip losslessly aborts
  the whole `--write` invocation;
- validation is baseline-relative: `apply` checks the original bundle
  first and only aborts on normative diagnostics the candidate introduces
  that the baseline didn't already have;
- concurrency-safe by construction: a hardlink-based candidate tree is
  built, re-validated, and every touched file is content-hash-checked
  immediately before an atomic rename replaces it;
- `--type`/`--field`/`--from`/`--to` sugar for the single most common case
  (rewrite one field's value on one type) compiles to the same `UPDATE`
  `apply` runs for hand-written SQL — no separate code path.

Also exposed as `apply_bundle()` in `okf_parser.service` and the MCP-free
Python API in `okf_parser.apply`.
