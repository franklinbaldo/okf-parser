# Rival

A `Rival` concept records one published tool that reads Open Knowledge Format
bundles. Concepts of this type live in `benchmarks/rivals/` and are named by
their distribution.

The type exists because this repository was wrong about its own competition.
The README named three tools and that prose list went stale. A list living in
the bundle can be queried, counted, validated, and consumed directly by the
benchmark runner.

## Frontmatter

- `type` — always `Rival`.
- `title` — the distribution name.
- `description` — what the tool claims to do.
- `registry` — package registry, currently `pypi` or `npm`.
- `package` — distribution name as published.
- `executable` — command installed by the package for the direct capability matrix.
- `version_measured` — version last exercised by the direct matrix.
- `surface` — advertised subcommands, transcribed from the tool's own help.
- `homepage` — upstream project location when known.
- `measured` — whether the direct scripted matrix interrogates it today.
- `agentic_enabled` — whether it participates in the current agentic benchmark round.
- `agentic_version` — exact package version pinned for the agentic round.
- `agentic_executable` — executable whose real invocation is observed by the runner.
- `agentic_instruction` — the minimal tool-specific constraint added to the common handoff.

## One registry, two measurement modes

The direct capability matrix and the agentic benchmark deliberately share this
type but do not overload one status field. `measured` and `version_measured`
refer to the direct scripted matrix. The `agentic_*` fields configure the
agentic round. Run evidence itself lives in immutable JSONL, so a completed run
does not mutate this registry into a result database.

Adding a new rival or testing a new release therefore means editing one `Rival`
concept. The runner must not maintain a second package/version/executable list.
The no-tool baseline is generated by the benchmark protocol and is not recorded
as a `Rival`, because absence of an OKF tool is a control condition, not a
competitor.

## Why the surface and agentic configuration are data

`surface` is evidence behind direct `unsupported` verdicts. The `agentic_*`
fields are reproducibility inputs: package, version, executable and handoff
constraint must be queryable from the same bundle that names the competitor.
Framework-specific adapter code remains code; competitor identity and pinned
configuration remain data.

## Declared columns

This type declares `docs/types/rival.schema.sql`, giving the registry typed
relational columns. Benchmark code reads `Rival` concepts through okf-parser
itself rather than parsing frontmatter independently.
