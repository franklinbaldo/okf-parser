# Rust Markdown facts MVP — 2026-08-08

Environment: Linux x86_64 workspace, warm filesystem cache, Python 3.12.13,
Node 24.14.0, Rust 1.97.1, 10,000 generated concepts, four linked body
paragraphs per concept, median of repeated same-process rounds. The Rust time
includes JSON serialization, one subprocess startup, parsing, and JSON decoding.

## Stage benchmark

| Runtime | Native facts | Rust batch | Speedup |
| --- | ---: | ---: | ---: |
| Python | 1,056 ms | 60 ms | 17.53× |
| TypeScript | 113 ms | 38 ms | 2.97× |

## Full bundle load

Before timing, the benchmark compares the complete native and Rust-assisted
bundle outputs. Concepts, reserved documents, links, and diagnostics must be
identical.

| Runtime | Native load | Rust-assisted | Speedup | Reduction |
| --- | ---: | ---: | ---: | ---: |
| Python | 4,460 ms | 2,678 ms | 1.67× | 40.0% |
| TypeScript | 1,731 ms | 1,236 ms | 1.40× | 28.6% |

These are MVP measurements on one warm-cache host, not release thresholds. They
justify continuing the narrow batch experiment, but not replacing native
fallbacks or moving filesystem orchestration into Rust. The next gates are a
larger shared conformance corpus, RSS/copy accounting, 100K documents, and
prebuilt binary packaging.
